# Ligature Restructuring Plan: HSK + CCCEDICT → all_ligatures.json

## Overview

This document describes the pipeline for generating GSUB ligature rules in variant-1 fonts. The source of truth is `sources/data/hsk_words.json` (HSK 3.0 vocabulary with authoritative pinyin). CCCEDICT provides additional coverage for words not in HSK. HSK entries always take priority when the same word appears in both sources.

## Target Architecture

### Data Flow

```
hsk_words.json
      │
generate_hsk_ligatures.py
      │
sources/data/hsk-ligatures.json
      │
      ├──────────────────────────────┐
      │                              │
      │         sources/data/cccedict-ligatures.json
      │         (generated by generate_cccedict_ligatures.py
      │          from CCCEDICT via pycccedict)
      │                              │
      └──────────┬───────────────────┘
                 │   merge_ligatures.py
                 │   (HSK entries take priority on overlap)
                 ▼
         sources/data/all_ligatures.json
                 │
         add_ligatures.py
                 │
         GSUB ligature rules in variant-1 TTF
```

## Step 1 — Generate `hsk-ligatures.json` from `hsk_words.json`

**Script**: `sources/scripts/generate_hsk_ligatures.py`

**Input**: `sources/data/hsk_words.json` + `sources/data/heteronym_map.json`

**Logic**:
- For each HSK entry with `len(simplified) >= 2`:
  - Extract tone-marked pinyin from `forms[0].transcriptions.pinyin` (already tone-marked; no conversion needed)
  - Build the `primary_reading` by joining the primary readings from `heteronym_map` for each character
  - Skip the word if any character is missing from `heteronym_map`, or if the pinyin token count doesn't match the character count
  - Include the word if the `hsk_reading` differs from `primary_reading` for any token

**Output format** (`hsk-ligatures.json`) — 915 entries, all with `hsk_level` 1–9:
```json
[
  {
    "simplified": "爸爸",
    "hsk_level": 1,
    "primary_reading": "bà bà",
    "practical_reading": "bà ba"
  },
  {
    "simplified": "高兴",
    "hsk_level": 1,
    "primary_reading": "gāo xīng",
    "practical_reading": "gāo xìng"
  }
]
```

Note: no `traditional` field. The contextual reading field is named `practical_reading` (not `hsk_reading`).

Both `primary_reading` and `practical_reading` are space-separated tone-marked pinyin strings, one token per character.

**Run**:
```bash
python sources/scripts/generate_hsk_ligatures.py \
    --hsk sources/data/hsk_words.json \
    --heteronym sources/data/heteronym_map.json \
    --output sources/data/hsk-ligatures.json \
    --verbose
```

## Step 2 — Generate `cccedict-ligatures.json` from CCCEDICT

**Script**: `sources/scripts/generate_cccedict_ligatures.py`

**Input**: CCCEDICT (via `pycccedict`) + `sources/data/heteronym_map.json`

**Logic**:
- Iterates all multi-character CCCEDICT entries
- Converts tone-numbered pinyin (e.g. `jue2`) to tone-marked (e.g. `jué`) using combining-diacritic decomposition
- Builds `primary_reading` by joining `heteronym_map` primary readings per character
- Includes the word if `hsk_reading` (CCCEDICT-derived) differs from `primary_reading`
- Sets `hsk_level` from HSK data when the word is also in HSK; uses `0` for non-HSK words

**Output format** (`cccedict-ligatures.json`) — 11,834 entries:
- 911 entries overlap with HSK (carry the HSK level)
- 10,923 entries are CCCEDICT-only (`hsk_level: 0`)

The contextual reading field is named `hsk_reading` (kept as-is from CCCEDICT processing). Unlike `hsk-ligatures.json`, this file retains the `traditional` field and uses `hsk_reading` rather than `practical_reading`:

```json
[
  {
    "simplified": "觉得",
    "traditional": "覺得",
    "hsk_level": 0,
    "primary_reading": "jiào de",
    "hsk_reading": "jué de"
  },
  {
    "simplified": "啰唆",
    "traditional": "囉唆",
    "hsk_level": 7,
    "primary_reading": "luō suō",
    "hsk_reading": "luō suo"
  }
]
```

**Run**:
```bash
python sources/scripts/generate_cccedict_ligatures.py \
    --heteronym sources/data/heteronym_map.json \
    --output sources/data/cccedict-ligatures.json \
    --verbose
```

## Step 3 — Merge into `all_ligatures.json`

**Script**: `sources/scripts/merge_ligatures.py` (to be created)

**Inputs**:
- `sources/data/hsk-ligatures.json` (915 entries; field: `practical_reading`)
- `sources/data/cccedict-ligatures.json` (11,834 entries; 911 overlap with HSK; field: `hsk_reading`)

**Logic**:
- Index HSK entries by `simplified`
- For each CCCEDICT entry: skip if `simplified` already present in HSK index (HSK wins on overlap)
- Normalize field names on merge: CCCEDICT `hsk_reading` → `practical_reading` in output; drop `traditional` from CCCEDICT entries
- Concatenate: all 915 HSK entries first, then the ~10,923 CCCEDICT-only entries
- Result: ~11,838 entries

There are a small number of words where HSK and CCCEDICT give different readings; the HSK `practical_reading` is used in all such cases.

**Output**: `sources/data/all_ligatures.json` — unified flat schema using `practical_reading` throughout (no `traditional` field).

**Run**:
```bash
python sources/scripts/merge_ligatures.py \
    --hsk      sources/data/hsk-ligatures.json \
    --cccedict sources/data/cccedict-ligatures.json \
    --output   sources/data/all_ligatures.json \
    --verbose
```

## Step 4 — Add Ligatures to Variant-1 Font

**Script**: `sources/scripts/add_ligatures.py` (refactor existing)

**Input**: `sources/data/all_ligatures.json` (replaces `duoyinzi_combined.json`)

**What changes in add_ligatures.py**:
- Replace `load_rules(duoyinzi_combined.json)` with `load_rules(all_ligatures.json)`
- New `load_rules()` reads the flat schema:
  - `simplified` → character sequence (one Unicode scalar per char)
  - `practical_reading` → space-split to get the contextual reading for each character position
  - `primary_reading` → space-split to detect which positions differ and need a non-default ruby
- Keep ligature glyph construction and GSUB injection logic unchanged

**Run** (unchanged interface):
```bash
python sources/scripts/add_ligatures.py \
    --font     output/NanGuoSansPinyin-1.ttf \
    --combined sources/data/all_ligatures.json \
    --syllables sources/data/syllable_inventory.json
```

## File Format Reference

The two source files have slightly different schemas; `all_ligatures.json` uses the unified output schema.

### `hsk-ligatures.json` (915 entries)

| Field | Type | Description |
|-------|------|-------------|
| `simplified` | string | Simplified Chinese word |
| `hsk_level` | int | HSK level 1–9 |
| `primary_reading` | string | Space-separated tone-marked pinyin built from `heteronym_map` primary readings |
| `practical_reading` | string | Space-separated contextual pinyin from HSK 3.0 authoritative data |

No `traditional` field.

### `cccedict-ligatures.json` (11,834 entries)

| Field | Type | Description |
|-------|------|-------------|
| `simplified` | string | Simplified Chinese word |
| `traditional` | string | Traditional Chinese word |
| `hsk_level` | int | HSK level 1–9 for words also in HSK; `0` for CCCEDICT-only entries |
| `primary_reading` | string | Space-separated tone-marked pinyin built from `heteronym_map` primary readings |
| `hsk_reading` | string | Space-separated contextual pinyin derived from CCCEDICT tone-number conversion |

### `all_ligatures.json` (unified output, ~11,838 entries)

| Field | Type | Description |
|-------|------|-------------|
| `simplified` | string | Simplified Chinese word |
| `hsk_level` | int | HSK level 1–9; `0` for CCCEDICT-only entries |
| `primary_reading` | string | Space-separated tone-marked pinyin built from `heteronym_map` primary readings |
| `practical_reading` | string | Space-separated contextual pinyin (from HSK for HSK entries; CCCEDICT-derived for others) |

No `traditional` field. `primary_reading` and `practical_reading` always have the same number of space-separated tokens as `len(simplified)` characters.

## Priority & Conflict Resolution

911 words appear in both files. Where the two sources give different contextual readings for the same word, the HSK `practical_reading` is authoritative.

| Rule | Behaviour |
|------|-----------|
| HSK entry present | Use HSK reading; discard CCCEDICT entry for that word |
| CCCEDICT only (`hsk_level: 0`) | Use CCCEDICT reading |
| Different reading, same word | HSK wins |

Rationale: HSK 3.0 pinyin is pre-marked and editorially reviewed. CCCEDICT tone-number → tone-mark conversion can misplace marks on diphthongs (e.g. 儿化 words like 男孩儿, 女孩儿, 没法儿 differ). HSK entries are never overridden.
